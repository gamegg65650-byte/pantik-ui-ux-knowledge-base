## Reading order

1. Start with the Overview and At a Glance to learn the structure.
2. Use the Recommendation for the exact requirement, level, definitions and exceptions.
3. Use Understanding for intent and examples and Quick Reference for filters.
4. Use Techniques, Failures and ACT rules to develop test cases. Check the relationship between each individual rule and the criterion.
5. Use the methodology and conformance documents when defining scope and documenting a claim.

## Source files

Originals and supporting source code are maintained by the [W3C Accessibility Guidelines Working Group](https://www.w3.org/groups/wg/ag/) in the [WCAG repository](https://github.com/w3c/wcag) and [WAI website repository](https://github.com/w3c/wai-website/tree/main/pages/standards-guidelines/wcag). The published standards also have dated revisions. When citing an audit, record the edition and link directly to the criterion.

W3C originals retain their own licenses and attribution. PANTIK audit notes, audit actions and the knowledge map are independent project documentation.

## Download the source snapshot

[W3C source snapshot (ZIP)](W3C-WCAG-source-snapshot.zip) contains 762 original source files and two attribution and verification files. It includes the WCAG 2.2 criterion and glossary sources, 87 matching Understanding pages including Parsing, 433 indexed technique and failure documents, and the WAI overview-family sources and translations available in the upstream folder. The archive preserves original source bytes and includes a path and Git blob manifest.

Use the published links above for the rendered Recommendations, examples, external dependencies, and linked collections such as ACT and supplemental guidance. The snapshot contains editorial source files.
